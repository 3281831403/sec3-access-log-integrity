有人偷偷删掉自己那条访问记录，日志校验还是显示全部完好，追责时少了关键一条：每条记录必须带序号与前一条摘要；序号必须连续且从一开始；删除或替换必须能定位到序号；整份摘要必须覆盖全部记录；写入必须追加不得覆盖；批量校验各日志独立。不变量：任何单条改动都会被检出并给序号；整份摘要随任意一条变化。

日志是按写入顺序排列的记录列表，每条记录含 index、prev、entry、hash 四个字段。空日志写入的第一条记录，prev 为 64 个字符 0。entry 为任意可 JSON 序列化的访问事件。日志的序号从 1 开始，末条序号加一就是下一条记录的序号，序号只由日志本身决定。

entry_hash 接收前序摘要、序号与 entry，返回 64 位小写十六进制摘要。append 在日志末尾追加一条记录并返回同一个列表。verify 返回含 ok 与 index 的映射：ok 为 True 时 index 为 None，否则 index 为首个断点序号。log_digest 返回整份日志的摘要，同一份日志重复计算结果相同，任意一条记录任意字段变化结果都不同。check_gap 返回缺失序号组成的升序列表。check_immutable 返回不可改写问题的文本列表。validate_log 返回问题文本列表，覆盖缺序号、重复序号与摘要长度错误。log_batch 接收名称到日志的映射，返回名称到校验结果的映射，每份日志独立校验。

运行方式：在仓库根执行 python -m pytest tests -q。当前 5 条公开测试全部失败，契约实现后应全部通过。
